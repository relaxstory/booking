# Re:LAX Story Lab schedule — 規格書

> 狀態：規格已確認（尚未開發）　最後更新：2026-11-18

## 1. 概述

劇本殺場次預約網站。供不特定玩家瀏覽時間表、登記包場、申請加入拼場；管理者（店主，未來可增加其他管理人員）於後台管理預約、拼場、關閉時段與劇本。

- 場地同時只能開一場 → 時間表為**單一軌道**，任何時段只能有一組。
- 不經手金流，收費於網站外處理。

## 2. 系統架構

```
GitHub Pages（前台時間表 + 登記表單 + 後台，靜態網頁，預設網域 *.github.io）
        │  HTTPS
Google Apps Script（後端：驗證、衝突檢查、通關碼、寄信、排程提醒、個資清除）
        │
Google Sheets（資料儲存）
```

- 前端不直接存取 Sheets；所有讀寫經由 Apps Script，前台只取得公開欄位。
- GitHub repo 為公開，repo 內不得含個資或密鑰。
- 寫入預約時以 `LockService` 鎖定，確保同時段不重複預約。
- 未來擴充（非第一階段）：LINE 官方帳號圖文選單連結至網頁 → 視需要以 LIFF 取得 LINE 身分並改用 LINE 通知。

## 3. 名詞與狀態

| 類型 | 狀態 | 前台顯示 | 佔用時段 |
|------|------|----------|----------|
| 包場 | 待確認 | 劇本名稱 +「待確認」 | 是 |
| 包場 | 已預約 | 劇本名稱 +「已預約」 | 是 |
| 拼場 | 拼團待確認 | 不顯示 | **否** |
| 拼場 | 待拼團 | 劇本名稱 + 人數與男女缺額（如「2/6・缺 男2 女2」）+ 主揪暱稱 +「申請加入」按鈕 | 是 |
| 拼場 | 已預約 | 劇本名稱 +「已預約」（由管理者手動轉換） | 是 |
| 任一 | 已拒絕／已取消 | 不顯示 | 否（釋出） |
| 關閉時段 | — | 「不開放」（原因不公開） | 是 |

前台「待確認」與「已預約」必須以不同樣式標示。

## 4. 時間規則

- 每場佔用時間 = 開始時間 + 劇本時長（清場時間已含在劇本時長內，不另加緩衝）。
- 開場時間只能為整點或半點（:00 / :30），範圍 09:00–19:00；營業時間本身不限制，結束時間可晚於 19:00（例：19:00 開場的 4 小時劇本至 23:00）。
- 可預約日期：最早為明天（不可登記當天場次，例：11/18 的場次最晚須於 11/17 登記），最晚至「本月 + 6 個月」的月底（例：11 月可預約至隔年 5/31）。
- 申請加入拼場同樣須於場次前一天（含）以前送出。
- 劇本人數為固定值（每個劇本一個人數）。
- 新增或修改預約、拼場、關閉時段時，皆不得與既有佔用時段重疊（前後台共用同一檢查）。
- 時間表以區塊呈現，區塊長度與時長成正比。

## 5. 前台

### 5.1 時間表
- 依日（或週）顯示單一時間軸，呈現第 3 節各狀態區塊。
- 拼場區塊僅顯示暱稱，不公開任何聯絡資料；玩家透過店家官方管道聯繫。
- 拼場顯示男女缺額：缺 男 = 劇本男性人數 − 已加入男性人數；女同理（只計「已加入」，不含申請中；小於 0 時顯示 0）。

### 5.2 包場登記

玩家先與店主私下談妥時間後，再上網登記。

| 欄位 | 必填 | 公開 |
|------|------|------|
| 劇本 | ✓ | ✓ |
| 日期 | ✓ | ✓ |
| 開始時間（:00／:30） | ✓ | ✓ |
| 姓名 | ✓ | ✗ |
| 暱稱 | ✓ | 僅拼場時顯示 |
| 電話 | ✓ | ✗ |
| Email | ✓ | ✗ |
| LINE ID／IG 帳號 | 兩者擇一必填 | ✗ |
| 人數 | ✓ | 拼場時顯示人數 |
| 男性人數 | ✓ | ✗ |
| 女性人數 | ✓ | ✗ |
| 備註 | | ✗ |
| 通關碼 | | — |

**輸入檢查**
- 男性人數 + 女性人數必須等於填寫的人數，否則即時顯示錯誤、無法送出（前端即時檢查，後端再檢查一次）。
- 劇本選單只列出「上架」中的劇本。
- 不對照劇本的男女人數（包場、拼團登記與申請加入皆同），由管理者自行判斷。

**送出後的結果**

| 情況 | 狀態 | 佔用時段 | 前台 |
|------|------|----------|------|
| 人數已滿 + 有效通關碼 | 已預約（通關碼失效） | 是 | 已預約 |
| 人數已滿 + 無通關碼 | 待確認 | 是 | 待確認 |
| 人數不足（不使用通關碼） | 拼團待確認 | **否** | 不顯示 |

- 「拼團待確認」不佔時段，因此可能與其他登記重疊；管理者確認時重新檢查衝突，有衝突則無法確認，只能拒絕或改時間。
- 管理者確認後成為「待拼團」，開始佔用時段並公開於前台。

**人數規則**

| 填寫人數 | 結果 |
|----------|------|
| = 劇本人數 | 包場（依通關碼決定已預約或待確認） |
| < 劇本人數 | 拼團待確認：登記者為主揪；管理者確認後成為待拼團 |
| > 劇本人數 | 錯誤，無法送出 |

- 通關碼僅適用於人數已滿的包場；人數不足卻填了通關碼時，提示錯誤，且不消耗通關碼。

- 待拼團的人數不會因玩家操作而增加；由管理者在後台調整人數，湊齊後手動改為「已預約」（成團），或在拼團失敗時取消。

- 送出後畫面顯示結果（已預約／已送出待確認）。
- 玩家不可自行取消或修改，須聯繫店主由後台處理。

### 5.3 申請加入拼場

- 待拼團區塊提供「申請加入」表單；欄位同 5.2 去除劇本、日期、時間、通關碼。可一次帶多人（人數 ≥ 1，不得超過剩餘名額）。
- 送出後為「申請中」，**不計入**場次人數；寄送「已申請加入」通知信。
- 管理者於後台核准（計入人數）或拒絕。

### 5.4 防灌單
- 隱藏陷阱欄位（honeypot）。
- 同一 Email 送出頻率限制。
- 若仍有問題再加 reCAPTCHA。

## 6. 後台

- 以 Google 帳號登入；可登入的帳號由管理者名單（admins 工作表）控制，目前為店主一人，未來可新增其他管理人員。
- 管理人員不區分權限，皆有完整權限。

功能：
- **時間表檢視**（週／月），含所有預約、拼場、關閉時段。
- **待確認清單**：包場待確認與拼團待確認，確認／拒絕；拼團待確認若與既有時段衝突需標示。
- **預約管理**：新增、修改（時間、劇本）、取消、檢視聯絡資料。
- **拼場管理**：建立場次、新增／移除參與者（欄位同 5.2）、標記主揪、核准／拒絕加入申請、調整人數、改為已預約。
- **關閉時段**：新增／刪除，可附僅後台可見的備註。
- **通關碼**：產生一次性代碼，產生後 7 天內有效，不綁定日期。
- **劇本管理**：劇本內容於 Google Sheet 編輯；後台提供上架／下架開關，可隨時切換，下架的劇本不出現在前台選單（已存在的場次不受影響）。
- 不需付款標記。

## 7. 通知（Email）

| 時機 | 收件者 |
|------|--------|
| 預約成立（通關碼直接成立，或店主確認） | 登記者 |
| 拼團待確認被確認（公開招募） | 主揪 |
| 店主拒絕 | 登記者 |
| 店主修改時間 | 該場所有人 |
| 店主取消 | 該場所有人 |
| 送出加入拼場申請 | 申請者（「已申請加入」） |
| 加入申請被核准／拒絕，或被管理者直接加入拼場 | 該參與者 |
| 拼場成團（轉為已預約） | 該場所有人 |
| 拼團失敗取消 | 該場所有人 |
| 開場前一日提醒 | 該場所有人 |

- 待確認送出時不寄信，僅畫面提示。
- 以 Apps Script `MailApp` 寄送（一般 Gmail 帳號約 100 封／日）；前一日提醒以時間觸發器執行。

## 8. 資料（Google Sheets 工作表）

| 工作表 | 主要欄位 |
|--------|----------|
| scripts 劇本 | id（系統用，與官網劇本網址代號相同）、劇本名稱、人數、時長（分）、男性人數、女性人數、價格（每人）、是否上架；官網目錄欄位：官網顯示狀態、精選、排序、標記、簡介、類型、玩家性別建議、系列、繁化、難度、主持人、介紹 |
| sessions 場次 | id、類型（包場／拼場）、劇本 id、開始時間、結束時間、狀態、建立時間、更新時間、使用的通關碼 |
| participants 參與者 | id、場次 id、狀態（已加入／申請中／已拒絕）、是否主揪、姓名、暱稱、電話、Email、LINE ID、IG、人數、男性人數、女性人數、備註 |
| closures 關閉時段 | id、開始時間、結束時間、備註（不公開） |
| passcodes 通關碼 | 代碼、建立時間、到期時間（建立 + 7 天）、使用時間、使用場次 id |
| admins 管理者 | Google 帳號 Email、名稱、啟用 |

前台顯示劇本名稱、人數、時長、男女人數、價格。

官網（https://relaxstory.github.io/）建置時以 `GET ?action=catalog` 讀取劇本目錄，`scripts` 工作表是劇本的唯一主資料。

## 9. 個資保存

- 場次結束滿半年後，自動刪除參與者的個資（姓名、電話、Email、LINE、IG、備註）。
- 保留場次紀錄：劇本、日期時間、類型、人數、狀態，供統計使用。
- 以時間觸發器每日執行清除。
- 前台需放隱私權聲明，說明蒐集目的與保存期限。
